# Future Scope

## 1. Purpose

This document records valuable extensions that should not expand the fast-track MVP.

The MVP already supports:

* authenticated users
* long-term history
* multiple sequential goals

Nothing below should be implemented unless explicitly promoted into Core Scope.

---

# 2. Saved Meals

Store frequently consumed meals for one-click reuse.

Likely one of the highest-value early enhancements.

---

# 3. Food Library

Reusable foods with:

* serving size
* calories
* protein
* carbohydrates
* fat

---

# 4. Recipes

Compose reusable recipes from multiple foods and calculate servings.

---

# 5. Rich Macro Tracking

Expand beyond optional protein to:

* carbohydrates
* fat
* fibre
* custom targets

---

# 6. Apple Health / Fitness Integration

Automatically ingest:

* Move energy
* weight
* steps
* workouts

---

# 7. Apple Health Export Import

Potential simpler bridge before direct integration.

---

# 8. Weekly Review

Structured review containing:

* calorie adherence
* Move adherence
* weight trend
* goal status
* optional user reflection

---

# 9. Advanced Goal Types

Potential future goal modes:

* weight loss
* weight maintenance
* weight gain
* activity consistency
* calorie awareness

These may eventually alter calculation and Dashboard behaviour.

---

# 10. Target History

If users frequently modify targets during a goal, introduce target-history records so that historical charts precisely reflect the target active on each day.

---

# 11. Adaptive Energy Expenditure

Estimate personalised maintenance expenditure from accumulated:

* food intake
* Move data
* weight changes

This could become a meaningful technical differentiator.

---

# 12. Weight Smoothing

Introduce:

* 7-day moving averages
* trend weight
* short-term fluctuation filtering

---

# 13. Projection Engine

Estimate:

* current trend
* projected target date
* projected weight at future dates

Use observed trends rather than simplistic linear extrapolation alone.

---

# 14. Natural-Language Meal Entry

Example:

`Two eggs, toast, half an avocado and coffee`

AI proposes structured meal information.

User reviews before saving.

---

# 15. AI Weekly Summary

Potential AI output:

* behavioural pattern summary
* adherence observations
* progress description
* areas for reflection

Avoid diagnostic or prescriptive medical behaviour.

---

# 16. Meal Photo Assistance

Potential future workflow:

1. upload photograph
2. identify likely foods
3. estimate portions/calorie range
4. user reviews
5. save approved data

---

# 17. Meal Planning

Plan daily or weekly meals against targets.

---

# 18. Grocery Planning

Generate lists from planned meals.

---

# 19. Notifications

Possible:

* meal logging reminder
* Move reminder
* weigh-in reminder
* weekly review reminder

---

# 20. Richer Motion and Visualisation

The MVP should establish the motion language.

Later versions may add:

* graph morphing between time ranges
* richer goal journey transitions
* interactive historical timelines
* animated comparisons between goals
* motion-driven onboarding

These should build upon the same core design system rather than introducing unrelated animation styles.

---

# 21. Personalisation

Possible user-selectable:

* colour themes
* Dashboard arrangements
* widget emphasis
* animation intensity
* preferred goal visualisation

---

# 22. Social / Shared Use

If the product evolves beyond independent personal accounts:

* optional profile sharing
* shared goals
* accountability partners
* coach/client relationships

These require separate privacy and permission design.

---

# 23. Cloud Deployment and Production Hardening

When moving beyond local development:

* hosted frontend
* hosted API
* managed database
* secure production secrets
* email verification
* password recovery
* monitoring
* backups
* rate limiting
* security review

---

# 24. Native Mobile Application

A native client may eventually improve:

* rapid meal entry
* notifications
* Apple Health access
* camera-based workflows

The responsive web experience should prove the core product first.

---

# 25. Productisation

Much later possibilities:

* onboarding flows
* subscription model
* premium analytics
* integrations marketplace
* family/shared plans
* health professional collaboration

These are explicitly outside the current project objective.
